## Day 02: Microsoft Sentinel

Let's not waste much time today. Begin able to understand Microsoft Sentinel, it's capabilities, and use cases are vital in passing the SC-200 exam. The most impactful thing that can be done around learning it is getting our hands dirty, so let's jump right in

## Configurating Sentinel

Before we can use the actual Sentinel SIEM tool we need to first create a `Log Analytics Workspace` in Azure.

1. In Azure search for "**Log Analytics Workspaces**" and create a new workspace.

2. Next, we need to **_connect Sentinel to the Log Analytics Workspace._**

<p align="center">
  <img src="../.images/CleanShot%202026-09-13%20at%2014.06.04@2x.png" alt="Connecting Sentinel to the Log Analytics Workspace" width="800">
</p>

- **_Note_**: Microsoft Sentinel is it's own service within Azure, and will show up as it's own resource within a resource group.

3. On the side menu, go to "all services" > search `"Microsoft Sentinel"` > Click on the Log Analytics Workspace you've just created > Click `Add` (Bottom of the page.)

## Next Steps

After Sentinel has been connected to your Log Analytics Workspace, we can go to the Microsoft Sentinel service again. You'll notice that, in the "overview" page, "Click here to go to the Defender portal" is highlighted.. Now we're cooking!

<p align="center">
  <img src="../.images/CleanShot%202026-09-13%20at%2014.16.36@2x.png" alt="Defender portal link highlighted in Microsoft Sentinel overview" width="800">
</p>

If we go to security.microsoft.com > "System" > "Settings", you'll notice that "Microsoft Sentinel" is now a settings option. Our SIEM is official set up and ready to be configured
